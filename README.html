Expense Tracker

Personal expense tracking for UTF-16 CSV bank statements — simple, private, and yours to customize.

Get Up and Running in 3 Steps

No programming knowledge required. You just need the bank CSV files that you download from UTF-16 CSV.

1

Install (once)

Double-click install.sh (or right-click → Open With → Terminal). This sets up everything automatically. You only need to do this once.

2

Add your bank statements

Download your account movements from UTF-16 CSV as a CSV file and drop it into the raw/ folder.

3

Run & open

Double-click run.sh. It imports your data and creates (or updates) the expense-report.ods spreadsheet. Open it in LibreOffice Calc or upload it to Google Sheets.

That's it! Every time you get a new bank statement, just drop the CSV into raw/ and double-click run.sh again. Your previous data and any edits you've made are preserved.

Using the Spreadsheet

The expense-report.ods file is where you'll spend most of your time. Here's what you'll find inside:

The Data sheet — your transaction list

This is the main sheet with all your transactions, one per row. The most important columns are:

ColumnWhat it showsCan I edit it?
DateWhen the transaction happenedNo (imported from bank)
DescriptionCleaned merchant/transaction nameNo
AmountHow much was spent or receivedNo
CategoryWhat type of expense (e.g. Groceries, Health)Yes!
SubcategoryMore specific label (e.g. Pharmacy, Cafe)Yes!
NotesYour personal annotationsYes!
Merchant NoteA shared note for ALL transactions from this merchantYes!
Your edits are safe. When you manually change the Category, Subcategory, Notes, or Merchant Note columns and then run run.sh again, your edits are saved to the database first — they won't be lost.

Categorizing your expenses

New transactions come in as “uncategorized.” You have two ways to fix that:

  1. Edit directly in the spreadsheet — Just type a category in the Category column on any row. Great for one-off expenses.
  2. Add a rule — If you want all transactions from a certain merchant to be automatically categorized in the future, add a rule (see Categorization Rules below). This is the best approach for recurring expenses like groceries, subscriptions, etc.

All the sheets at a glance

The first time you run the tool, it generates several starter analysis sheets. You can customize, rename, or delete any of them (except Intro, Data, and Rules which are regenerated each time).

Add your own sheets! You can create as many custom sheets as you want with your own formulas and charts. The tool will never touch them.

Categorization Rules

Rules automatically categorize transactions based on text patterns. Instead of manually categorizing “CONTINENTE” every month, add a rule once and it's handled forever.

Adding rules the easy way

Open a Terminal in the project folder and type:

./run.sh                                                 # activate environment
python bank_ingest.py rules add CONTINENTE Groceries     # simple rule
python bank_ingest.py rules add FARMACIA Health --sub Pharmacy  # with subcategory

Or edit the file data/rules.csv directly in any spreadsheet or text editor:

pattern,match_field,category,subcategory,payment_type
CONTINENTE,description,Groceries,,card
FARMACIA,description,Health,Pharmacy,card
VODAFONE,description,Utilities,Phone,direct_debit
  • Rules match by case-insensitive substring — “CONTINENTE” matches “WWW.CONTINENTE.PT”
  • Rules are applied in order — the first matching rule wins
  • Rules only affect uncategorized transactions — they won't override your manual edits
  • After adding new rules, run ./run.sh to apply them

Using #Tags

Tags are a flexible way to label and track transactions beyond just categories. Add any word starting with # in the Notes or Merchant Note columns.

Examples

Tag ideas: #recurring #reimbursable #gift #shared #splurge #essential #one-off #work #vacation

The Tags sheet

The starter Tags sheet automatically counts and sums tagged transactions. It comes with a few example tags — just replace them with your own or add more rows.

Build your own tag formulas! In any custom sheet you can count tagged transactions with:
=COUNTIF(Data.R:R, "*#gift*") + COUNTIF(Data.S:S, "*#gift*")

Merchant Notes

Merchant notes are annotations that apply to all transactions with the same merchant name. Unlike per-transaction notes, a merchant note is shared across every occurrence.

  1. In the Data sheet, find the Merchant Note column (S)
  2. Type a note on any row (e.g. “Weekly groceries” next to a Continente transaction)
  3. Run ./run.sh — the note is saved
  4. On the next run, every row with that merchant gets the same note

Merchant notes are also great for #tags — tag a merchant once and all its transactions are tagged.

Account Holders (shared accounts)

If you share a bank account and want to see who made each purchase (based on the debit card used), set up card holders:

python bank_ingest.py cards add 1234 Alice
python bank_ingest.py cards add 5678 Bob

Or edit data/account-holders.csv directly:

card_last4,name
1234,Alice
5678,Bob

The “Who” column in the Data sheet will then show the cardholder's name. Transactions without a recognized card show “Joint.”

Backups

Your data is backed up automatically — no action needed:

  • Monthly backups — Every time you run ./run.sh, the system checks if last month has a backup. If not, it creates one automatically.
  • Safety backups — Before any operation that could change your data (like regenerating all sheets), a timestamped backup is created.
  • Manual backups — Run python bank_ingest.py backup at any time. Use --out ~/Desktop to save it somewhere specific.

Backups are zip files in the backups/ folder, containing your database, config files, raw CSVs, and the spreadsheet.

Technical Reference

Everything below is for users comfortable with the command line. The basics above are all you need to get started.

Shell Scripts

install.sh — First-Time Setup

Run this once when you first get the project (or on a new computer).

./install.sh

What it does:

  1. Checks that Python 3.9+ is installed
  2. Creates a virtual environment (.venv/)
  3. Installs Python dependencies (odfpy)
  4. Creates the raw/, data/, and backups/ directories
  5. Creates starter config files (rules.csv, account-holders.csv, etc.) in data/ if they don't exist
  6. Makes the shell scripts executable

run.sh — Import Data & Generate Report

The everyday script. Double-click it or run it from Terminal.

./run.sh

What it does:

  1. Scans raw/ for any new CSV files not yet imported
  2. Auto-renames them (e.g. EXPORT_0_1022026.csv → 2026-01.csv)
  3. Imports new transactions into the SQLite database
  4. Syncs any manual category edits from the ODS back into the database
  5. Applies categorization rules from data/rules.csv
  6. Regenerates the expense-report.ods report

update.sh — Pull Latest Code from GitHub

Run this occasionally to get the latest improvements.

./update.sh

What it does:

  1. Fetches changes from the GitHub remote
  2. If there are updates, pulls them safely (fast-forward only)
  3. Re-runs install.sh if dependencies changed
  4. If already up to date, does nothing

Python CLI Reference

The shell scripts use bank_ingest.py under the hood. You can also use it directly for more control. Always activate the virtual environment first: source .venv/bin/activate

Global flags (work with any subcommand):

FlagEffect
-q / --quietSuppress all output except errors
-v / --verboseShow detailed progress information

auto (default)

Scan for new files, import, and regenerate the report. This is what run.sh calls.

python bank_ingest.py              # same as 'auto'
python bank_ingest.py auto
python bank_ingest.py auto --raw path/to/csvs
python bank_ingest.py auto --no-backup    # skip automatic monthly backup
python bank_ingest.py auto --dry-run      # show what would happen, change nothing

The auto command automatically creates a monthly backup (e.g. backups/backup-2026-01.zip) for the previous month if one doesn't already exist. Use --no-backup to skip this. Use --dry-run to preview what would happen without making any changes.

ingest

Manually import specific CSV files.

python bank_ingest.py ingest raw/EXPORT_0_1022026.csv
python bank_ingest.py ingest raw/*.csv
python bank_ingest.py ingest --no-rename raw/some-file.csv
python bank_ingest.py ingest --dry-run raw/EXPORT_0_1022026.csv

The ingest command auto-renames files based on the date range inside the CSV (e.g. EXPORT_0_1022026.csv → 2026-01.csv). Use --no-rename to skip this.

report

Apply rules and regenerate the ODS report (without importing new data).

python bank_ingest.py report
python bank_ingest.py report --fresh
python bank_ingest.py report --no-sync
python bank_ingest.py report --fresh --no-sync
FlagEffect
--freshCreates a backup, then deletes the existing ODS and regenerates all sheets (including Dashboard, Monthly Summary/Trend, Category/Subcategory Breakdown, and any custom sheets). Manual edits are still saved to the database first.
--no-syncSkips reading manual edits from the ODS back into the database.

cards

Manage card-holder mappings (which debit card belongs to whom).

python bank_ingest.py cards                          # list all card holders
python bank_ingest.py cards add 1234 Alice           # add a card
python bank_ingest.py cards add 5678 Bob             # add another
python bank_ingest.py cards remove 1234              # remove a card

rules

Manage categorization rules from the command line.

python bank_ingest.py rules                                          # list all
python bank_ingest.py rules add CONTINENTE Groceries                 # simple rule
python bank_ingest.py rules add FARMACIA Health --sub Pharmacy --payment card
python bank_ingest.py rules remove CONTINENTE                        # remove by pattern
FlagDefaultDescription
--fielddescriptionField to match: description (cleaned) or description_raw
--sub(empty)Subcategory
--payment(empty)Payment type: card, transfer, direct_debit, fee, tax

export

Export all transactions to a clean UTF-8 CSV file.

python bank_ingest.py export
python bank_ingest.py export --out my-data.csv

reclean

Recompute all cleaned descriptions from the raw bank text using the current cleaning patterns. Use this after editing data/noise-words.txt or data/cleaning-patterns.csv.

python bank_ingest.py reclean

What it does:

  1. Creates a backup (in case the reclean changes something you didn't expect)
  2. Re-runs the description cleaner on every transaction in the database
  3. Updates only the rows where the cleaned description changed
  4. Regenerates the ODS report

All categories, notes, and other data are preserved.

backup

Create a zip archive of all your data.

python bank_ingest.py backup                   # save to backups/ (default)
python bank_ingest.py backup --out ~/Desktop    # save to a custom location

Cleaning Patterns (advanced)

When bank descriptions are imported, the parser cleans them up by stripping prefixes, noise words, and reference codes. These patterns are loaded from two external files so you can tweak them without touching Python code.

data/noise-words.txt — Simple word list

A plain text file with one word per line. These words are stripped from descriptions when they appear as standalone words (surrounded by spaces). Case-insensitive.

CONTACTLESS
PT
Portugal
PORTO
LISBOA
  • Add city names if you move to a different area
  • Remove words if they're being stripped from merchant names you want to keep
  • Lines starting with # are comments

data/cleaning-patterns.csv — Regex patterns

A CSV file for power users who need finer control over how descriptions are cleaned.

ColumnDescription
typeprefix (stripped from the start) or noise (stripped anywhere)
patternA regular expression
descriptionHuman-readable explanation of what the pattern does

Important: If your regex pattern contains commas (e.g. {8,12}), wrap the entire row in quotes.

Data Architecture

Bank CSV (raw/) → Python parser → SQLite (data/ledger.sqlite) → ODS report ↑ ↑ | data/account-holders.csv data/rules.csv | ↑ | ←— manual edits synced back ←’
  • Raw CSVs (raw/) — Immutable bank exports, kept as-is for reference
  • Account holders (data/account-holders.csv) — Maps card last-4 digits to owner names
  • Rules (data/rules.csv) — Defines how transactions get categorized
  • SQLite database (data/ledger.sqlite) — The single source of truth for all transactions
  • ODS report (expense-report.ods) — A generated spreadsheet for viewing and analysis

Troubleshooting

"No new files to ingest"
All CSV files in raw/ have already been imported. Drop a new one and run again.
"Could not find date range"
The CSV file doesn't have the expected UTF-16 header format. Use ingest --no-rename to import it with its original filename.
"File already exists with range..."
You're trying to import a CSV for a month that's already been imported with the same or wider date range. If you need to re-import, delete the existing file from raw/ first.
Formulas show #VALUE!
Make sure you're opening the file in LibreOffice Calc (not a text editor). If the issue persists, run python bank_ingest.py report --fresh to regenerate all sheets.
"externally-managed-environment" error
You're trying to install packages on system Python. Run ./install.sh to set up a virtual environment instead.
