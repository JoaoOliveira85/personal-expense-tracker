Expense Tracker

Personal expense tracking for Portuguese bank statements — simple, private, and yours to customize. Everything runs on your own computer; nothing is sent anywhere.

Get Up and Running in 4 Steps

No programming knowledge required. You just need the statement files (CSV or PDF) that you download from your bank.

1

Install (once)

Open a Terminal in the project folder and run ./install.sh (or right-click install.sh → Open With → Terminal). It sets up everything automatically. You only need to do this once.

2

Open the app

Run ./run.sh. The Expense Tracker opens in your browser at http://localhost:8501.

3

Add your bank statements

On the Import page, upload the CSV or PDF statements you downloaded from your bank (or drop them into the raw/ folder). If your bank emails you statements, the Tools page can fetch them for you.

4

Review and categorize

See where your money went on the Dashboard, sort out uncategorized merchants on the Categorize page, and download the spreadsheet or monthly PDF reports from the Tools page.

Prefer the command line? Drop your statements into raw/ and run ./run.sh auto. It imports every new file and writes expense-report.xlsx. Your previous data and any edits you've made are preserved.

The Spreadsheet Reports

The tracker can write your data to a spreadsheet in two formats:

ReportOpens inBest for
expense-report.xlsx (default)Excel, Numbers, Google Sheets, LibreOfficeViewing. Rewritten from scratch every time, so don't edit it.
expense-report.ods (--format ods)LibreOffice, Google SheetsEditing. Your category and note edits are saved back, and your own sheets are kept.

The Data sheet — your transaction list

This is the main sheet with all your transactions, one per row. The most important columns are:

ColumnWhat it showsCan I edit it? (ODS only)

Your edits are safe. When you change the Category, Subcategory, Notes, or Merchant Note columns in the ODS, they are saved to the database the next time the tracker runs — they won't be lost. Clearing a category hands that transaction back to the rules.

All the sheets at a glance

Both reports contain the same sheets. In the ODS, the analysis sheets are generated on the first run only, so you can customize, rename, or delete them; Intro, Data, and Rules are regenerated each time.

Add your own sheets! In the ODS you can create as many custom sheets as you want with your own formulas and charts. The tool will never touch them. Refer to whole columns there (Data.F:F) so new rows are always included.

Refunds and savings

  • Refunds — Money coming in with a spending category (e.g. a pharmacy refund categorized as Health) is subtracted from that category's spending, not counted as income.
  • Savings — Transactions categorized Savings count as neither spending nor income, so Net shows only what you earned and spent.

Categorizing Your Expenses

New transactions come in as “uncategorized.” You have three ways to fix that:

  1. The Categorize page — Pick a category for a merchant and every transaction from it is categorized. Tick the option to save it as a rule for future imports.
  2. Edit the ODS — Type a category in the Category column on any row. Great for one-off expenses.
  3. Add a rule — Categorize all transactions from a merchant automatically, now and in the future (see Categorization Rules). Best for recurring expenses like groceries and subscriptions.
Start with the starter rules. The project ships with ~200 rules for common Portuguese merchants and services (supermarkets, utilities, telecoms, fuel, transport, health, and more). Import them from the Tools page or with python bank_ingest.py rules import-starter. Then run python bank_ingest.py suggest to find recurring and frequent merchants that still need a rule.

Categorization Rules

Rules automatically categorize transactions based on text patterns. Instead of categorizing “CONTINENTE” every month, add a rule once and it's handled forever.

Adding rules

Use the Rules page, or type in a Terminal in the project folder:

source .venv/bin/activate                                # activate environment
python bank_ingest.py rules add CONTINENTE Groceries     # simple rule
python bank_ingest.py rules add FARMACIA Health --sub Pharmacy  # with subcategory

Or edit the file data/rules.csv directly in any spreadsheet or text editor:

pattern,match_field,category,subcategory,payment_type
CONTINENTE,description,Groceries,,card
FARMACIA,description,Health,Pharmacy,card
VODAFONE,description,Utilities,Phone,direct_debit
  • Matching is case-insensitive and a pattern must start at the beginning of a word: PAO matches “PAO QUENTE” and “PAOZINHO” but not “JAPAO”
  • End a pattern with a space (written quoted, e.g. "BP ") to also require it to end on a word boundary
  • When several rules match, the longest pattern wins (so UBER EATS beats UBER)
  • Rules never override your manual edits. Categories set by rules are re-checked on every run, so editing or deleting a rule fixes the transactions it had categorized
  • After adding new rules, regenerate the report (Tools page, or ./run.sh auto) to apply them

Using #Tags

Tags are a flexible way to label and track transactions beyond just categories. Add any word starting with # in the Notes or Merchant Note columns.

The Tags sheet

The starter Tags sheet automatically counts and sums tagged transactions. It comes with a few example tags — just replace them with your own or add more rows.

ColumnWhat it shows

Build your own tag formulas! In any custom sheet you can count tagged transactions with:
=COUNTIF(Data.R:R, "*#gift*") + COUNTIF(Data.S:S, "*#gift*")

Merchant Notes

Merchant notes are annotations that apply to all transactions with the same merchant name. Unlike per-transaction notes, a merchant note is shared across every occurrence.

  1. In the ODS Data sheet, find the Merchant Note column (S)
  2. Type a note on any row (e.g. “Weekly groceries” next to a Continente transaction)
  3. Run the tracker again — the note is saved to data/description-notes.csv
  4. On the next run, every row with that merchant gets the same note

Merchant notes are also great for #tags — tag a merchant once and all its transactions are tagged.

Account Holders (shared accounts)

If you share a bank account and want to see who made each purchase (based on the debit card used), set up card holders:

python bank_ingest.py cards add 1234 Alice
python bank_ingest.py cards add 5678 Bob

Or edit data/account-holders.csv directly:

card_last4,name
1234,Alice
5678,Bob

The “Who” column in the Data sheet will then show the cardholder's name. Transactions without a recognized card show “Joint.”

Monthly PDF Report

Want a quick one-page summary of a month's spending? Generate a PDF from the Tools page, or:

python bank_ingest.py pdf                      # previous month
python bank_ingest.py pdf --month 2026-01      # specific month
python bank_ingest.py pdf --all                # one PDF per month with data

The PDF shows at a glance: total income vs expenses, spending by category (with variation vs last month and vs average), your top merchants, any #tag totals, essential spending, and how many transactions still need a category.

Output: The PDF is saved to reports/report-YYYY-MM.pdf. Use --out path/to/file.pdf to save it somewhere else.

Fetching Statements from Email

If your bank emails you statements, the tracker can download them over IMAP and import them. Set it up once on the Tools page, or with:

python bank_ingest.py fetch --setup     # interactive setup
python bank_ingest.py fetch             # download new statements and import them

You'll need your email server (e.g. imap.gmail.com), your address, an app password (never your main password), and part of your bank's sender address. The settings are saved to data/email-config.json, readable by your user only and never committed to Git.

Financial Advisor Prompts

The advisor command turns a month of spending into a prompt you can paste into an AI chat of your choice, and keeps a context file of your goals so each month's advice builds on the last. The tracker never contacts an AI service itself — you decide what to share.

python bank_ingest.py advisor           # write a prompt for last month
python bank_ingest.py advisor ingest    # record the answer you saved
python bank_ingest.py advisor status    # see which months still need an answer

Backups

Your data is backed up automatically — no action needed:

  • Monthly backups — Every time ./run.sh auto runs, the system checks if last month has a backup. If not, it creates one automatically.
  • Safety backups — Before any operation that could change your data (regenerating all ODS sheets, re-cleaning descriptions, resetting), a timestamped backup is created.
  • Manual backups — Use the Tools page, or run python bank_ingest.py backup at any time. Use --out ~/Desktop to save it somewhere specific.

Backups are zip files in the backups/ folder, containing your database, config files, raw statements, and the ODS report.

Running on a Home Server

The tracker can run in Docker on an always-on machine (a NUC, a Raspberry Pi, etc.): the app stays available on your local network, and a daily job fetches statements, imports them and regenerates the reports. See DEPLOYMENT.md for the full guide.

The app has no login. Only make it reachable from a network you trust, and never expose it to the internet.

Technical Reference

Everything below is for users comfortable with the command line. The basics above are all you need to get started. Every command and flag is described in README.md.

Shell Scripts

install.sh — First-Time Setup

Run this once when you first get the project (or on a new computer).

./install.sh
./install.sh --branch main      # check out a specific branch first

What it does:

  1. Optionally checks out the given git branch
  2. Checks that Python 3.9+ is installed
  3. Creates a virtual environment (.venv/)
  4. Installs the Python dependencies from requirements.txt
  5. Creates the raw/, data/, data/advisor/, backups/, and reports/ directories
  6. Creates starter config files (rules.csv, account-holders.csv, etc.) in data/ if they don't exist
  7. Makes the shell scripts executable

run.sh — Everyday Use

./run.sh                # open the app in your browser (default)
./run.sh auto           # import new files + write the report, no app
./run.sh <command>      # run any bank_ingest.py command

./run.sh auto scans raw/ for new statements, auto-renames them (e.g. EXPORT_0_1022026.csv → 2026-01.csv), imports them, syncs edits from an existing ODS back to the database, applies the rules, and writes expense-report.xlsx (add --format ods or --format both for the ODS).

update.sh — Pull Latest Code from GitHub

Run this occasionally to get the latest improvements.

./update.sh

What it does:

  1. Finds the remote pointing at the development repo, or adds one named upstream
  2. Merges its main branch into your current branch, keeping any personal commits
  3. Aborts cleanly on a merge conflict, leaving your copy unchanged
  4. Re-runs install.sh if dependencies changed

Cleaning Patterns (advanced)

When bank descriptions are imported, the parser cleans them up by stripping prefixes, noise words, and reference codes. These patterns are loaded from two external files so you can tweak them without touching Python code. Run python bank_ingest.py reclean after editing them.

data/noise-words.txt — Simple word list

A plain text file with one word per line. These words are stripped from descriptions when they appear as standalone words (surrounded by spaces). Case-insensitive.

CONTACTLESS
PT
Portugal
PORTO
LISBOA
  • Add city names if you move to a different area
  • Remove words if they're being stripped from merchant names you want to keep
  • Lines starting with # are comments

data/cleaning-patterns.csv — Regex patterns

A CSV file for power users who need finer control over how descriptions are cleaned.

ColumnDescription
typeprefix (stripped from the start) or noise (stripped anywhere)
patternA regular expression (case-insensitive)
descriptionHuman-readable explanation of what the pattern does

Important: If your regex pattern contains commas (e.g. {8,12}), wrap the entire row in quotes.

Data Architecture

Bank CSV/PDF (raw/) → Auto-detect → Parser → SQLite (data/ledger.sqlite) → xlsx / ODS / PDF ↑ ↑ | data/account-holders.csv data/rules.csv | ↑ | ←— ODS edits synced back ←’
  • Raw files (raw/) — Immutable bank exports (CSV or PDF), kept as-is for reference
  • Account holders (data/account-holders.csv) — Maps card last-4 digits to owner names
  • Rules (data/rules.csv) — Defines how transactions get categorized
  • SQLite database (data/ledger.sqlite) — The single source of truth for all transactions, deduplicated
  • Reports — Generated views: expense-report.xlsx, the editable expense-report.ods, and monthly PDFs in reports/

The full project layout is in README.md; module details are in CONTRIBUTING.md.

Troubleshooting

"No new files to ingest"
All files in raw/ have already been imported. Drop a new one and run again.
"Could not find date range"
The file doesn't have a recognized bank header format. Use ingest --no-rename to import it with its original filename, or --bank <id> to choose the parser.
"No parser found for file"
The format couldn't be detected. Run python bank_ingest.py banks to see the supported formats, then use ingest --bank <id>.
"File already exists with range..."
You're trying to import a statement for a month that's already been imported with the same or wider date range. If you need to re-import, delete the existing file from raw/ first.
Formulas show #VALUE!
Make sure you're opening the file in a spreadsheet app (not a text editor). If an ODS keeps showing it, run python bank_ingest.py report --format ods --fresh to regenerate all sheets.
"externally-managed-environment" error
You're trying to install packages on system Python. Run ./install.sh to set up a virtual environment instead.
